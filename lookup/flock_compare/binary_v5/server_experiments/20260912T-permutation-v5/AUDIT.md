# Binary permutation v5 独立数据审计

本次组合候选在 N30、64 线程、六组相同输入中，核心证明、包含准备的证明，以及加上验证和全源检查的流水线均比本次旧基线与 Flock 更快（每项均 6/6）。收益主要体现为树层释放移出逐次证明并在批末合并执行；释放成本没有消失。寄存器候选单独的筛选结果为负，组合相对仅复用的额外收益尚未证实。

## 原始材料与校验

- 完整校验通过：9 个接受 case、71 条 proof record、17 项服务器测试、415 个归档源文件、110 个下载证据文件；无排除或重试样本。
- 校验了源码包与逐文件 SHA、下载证据 SHA、测试/构建/命令退出码、原始 JSON 与 JSONL 一致性、64 CPU 亲和性、ISA 元数据、预热标记、实际执行顺序、同输入证明摘要与实际 proof 文件字节一致性、独立 RSS 与主组重叠输入的证明身份。
- 筛选采用四系统 Williams 顺序；主组六轮采用全部三系统排列。候选依预先约定的 measured core **均值**规则选择，selection 的时间与报告 SHA 在主组之前。
- 冻结 summarizer 在内存中仅作 Python 3.10 日期解析兼容（末尾 `Z` 转成 `+00:00`）后运行完整校验；未修改任何冻结文件或原始证据。数字另外直接从原始样本重算。
- 源码包 SHA256：`21989af1a3db2b3c1e4a62ac6115d3806b8b7a3da1a8650acad01cf89350c249`。
- 可执行文件 SHA256：`57cc3e617f657fceddfdac55218c1fcae0186d804d51e8a3c75f231020a0e7df`。
- 下载结果包 SHA256：`7d66e2cf2a7b3111fda5296ace64bd5f360c6398c73ce94da60169414dd044e3`。

## 比较边界

- 本次所有 Mikros 变体同输入证明字节一致，N30 为 44,208 字节；Flock 为 16,176 字节。Mikros 更快不代表通信更少。
- Flock 是本快照 `product_gkr::prove_batched`，没有另做 skip/compression 对齐；双方证明同一 public permutation 关系，都是 PIOP 边界，完整源检查实际执行但没有 PCS 或完整 SNARK。
- 本文只比较同一 v5 实验进程计划中的数据；previous 调用冻结 v4 实现，但不是拿历史 v4 运行时间跨机器状态比较。默认公开 `prove` 仍为 `Engine::Fused`；候选通过显式 Engine 使用。
- 64 逻辑 CPU 对应 48 个物理核加 16 个 SMT 线程，跨两个 NUMA 节点各 32 个逻辑 CPU；固定 CPU 亲和性，没有显式内存绑定。没有把时间变化解释为已测缓存、NUMA 或硬件计数器变化。
- 六组主样本和单次冷/暖过程足以陈述本批结果，不构成跨机器、跨负载或统计显著性保证。
