# Mikros permutation v3：融合建树与 Flock 对比

将 v2 的解码、紧凑叶子写入、第一层系数乘积和求值，替换为一次融合扫描；保留紧凑叶子，直接生成第一层扩域乘积。仅 K64、128-bit 系数容量启用。原始证明字节、挑战顺序和验证器不变。

N=2^30、48 个物理核的核心耗时中位数：v2 11.263 s，v3 10.069 s，Flock 12.056 s。含原生输入转换的对应中位数为 13.442 / 12.292 / 13.262 s。源认证另列，尚未接入 PCS。

本轮 v3 相对 v2 的核心耗时中位数减少 10.6%，含转换减少 8.6%。峰值内存基本不变，仍比本次 Flock dense 实现低 57.3%。这是本次实现和配置的结果，不是协议的内存下界。

## 波动与阶段归因

| 物理核 | 系统 | 核心最小 s | 中位数 s | 最大 s |
|---:|---|---:|---:|---:|
| 24 | Mikros v2 流式 | 13.987 | 14.094 | 14.303 |
| 24 | Mikros v3 融合 | 11.812 | 11.993 | 12.039 |
| 24 | Flock | 12.477 | 12.608 | 12.750 |
| 48 | Mikros v2 流式 | 10.838 | 11.263 | 11.499 |
| 48 | Mikros v3 融合 | 9.919 | 10.069 | 10.156 |
| 48 | Flock | 11.854 | 12.056 | 12.165 |

48 核阶段中位数（秒）；融合构造将原来三个阶段合在一起，因此应该比较合计。阶段中位数之和不一定等于总中位数。

| 阶段 | v2 | v3 |
|---|---:|---:|
| 解码+首层系数构造+求值/融合构造 | 4.552 | 2.647 |
| 扩域上层建树 | 0.714 | 0.753 |
| GKR 消息/折叠 | 3.377 | 3.422 |
| 同步层释放 | 2.496 | 3.081 |
| prover 内源检查 | 0.139 | 0.134 |
| 缓冲获取 | 0.000 | 0.000 |

v3 取消每棵树首层的 8 GiB 系数临时数组，但两棵树依次构造、整个过程峰值可能出现在 GKR；因此不要推断进程峰值必然少 16 GiB。两版本均同步清理，清理时间保留在 core 内。

融合构造是实测加速来源：48 核该阶段由 4.552 s 降至 2.647 s。同步层释放却由 2.496 s 上升至 3.081 s，抵消部分收益；GKR 消息/折叠基本相近。未使用硬件计数器或内核跟踪，不把释放变化具体归因于某种缓存、NUMA 或分配器机制。下一步主要可优化项是输入转换、同步释放和源认证；证明大小的差距则需要修改 batching/消息协议。

## 理论优势的适用范围

Mikros 当前优势是较小的原生位表示、紧凑叶子和按层释放。当前两条独立三次 GKR 链的 proof 为 44,208 bytes，Flock 的 batched 二次 core 为 16,176 bytes，后者还将 f/g/σ 归约到同一行开点。

稿件的完整系数域方案给出单个 grand product 的 O(Nκ) BB + O(N) BE + (10N/κ + lower-order terms) EE；当前程序没有实现完整 packed Hadamard reduction，不能声称已经获得该 EE 计数或 κ 倍速度提升。详见 [THEORY.md](../../THEORY.md)。

## 可复核性与限制

本报告采用的 96 份本地/服务器证明全部重放 verifier、核验全部源声明并检查实际文件大小；与 v2 的 124 份重叠 proof 核对了原始字节 SHA256、input digest 和 proof digest。新旧 Mikros 证明及 transcript 相同。

因检测到其他 benchmark/build 进程而排除的完整尝试：main-n30-24t-attempt1。排除尝试的原始日志和数据保留在归档中，未计入上述统计或证明份数；脚本待空闲后重跑整组。

10 个服务器 case 成功。服务器 native AVX512/VPCLMUL 差分测试通过，本地差分测试及 Clippy 通过。结果归档 137 个文件的哈希检查通过。v1/v2 Rust 与冻结 Flock 文件逐项校验未变。

双路 Xeon Gold 6342，24 核固定单 NUMA 节点，48 核覆盖两节点，均使用物理核、不使用 SMT sibling。Rust nightly-2026-03-21、target-cpu=native。共享服务器：接受的 case 未检测到受监测的同用户 benchmark/build 干扰，并不声称主机完全独占。未测硬件性能计数器。
