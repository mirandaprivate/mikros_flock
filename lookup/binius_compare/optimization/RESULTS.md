## 为什么保留打包实现，但不默认启用

以下为独立的完整消融实验：11 种实现、11 个平衡顺序样本，N=2^20、8-bit。

| 实现 | 单线程总证明 ms | 六线程总证明 ms |
|---|---:|---:|
| reference | 1383.22 | 1330.35 |
| full_extension | 1051.83 | 1002.84 |
| direct | 887.82 | 834.83 |
| lookup | 563.76 | 432.01 |
| fused | 499.08 | 297.24 |
| batched | 481.16 | 295.45 |
| bridge | 333.52 | 161.89 |
| full_optimized | 249.58 | 143.44 |
| packed | 557.52 | 210.42 |

原版单线程 PIOP 的内部计时显示：解码约 176 ms，紧凑系数树构造约 190 ms，系数求值约 73 ms，层展开/复制约 158 ms；eq 表、消息和折叠约 32/94/51 ms。
因此，原版最重的部分包括数据转换和系数表示，不能把整个 PIOP 时间都归为 sumcheck 算术。

完整打包版在 K=GF(2^32) 的两层中按实际 kappa=2、4 分别跳过 1、2 轮，共 3 轮。
它的消息和融合折叠降至约 15/41 ms，但 quotient 预处理约 221 ms，投影约 35 ms，终端列求值约 53 ms，抵消了节省。
这些数来自单线程消融的独立阶段中位数；新归约已通过恒等式和终端认证测试，但当前工程实现尚非最快。

`FullOptimized` 的两棵树保留完整扩域层，内存占用高于紧凑树。没有把树层容量当作进程峰值内存，也没有把关闭存储压缩描述为实现了论文的全部性能收益。
系数打包算法和消息顺序见 [PACKED_REDUCTION.md](PACKED_REDUCTION.md)。

## 验证与复现

- 13 个测试函数，覆盖多个尺寸/子域、冻结基线差分、零/一 eq 坐标、形式多项式恒等式、两份终端认证，以及 PIOP/PCS 篡改。
- 格式检查、Clippy（本次两个 crate 的 all-targets / -D warnings）、release 测试和构建通过。
- 两套正式实验共有 684 个有效证明，包含 602 个计时样本和 82 个预热证明；全部序列化、反序列化并验证两份真实 PCS opening。
- 核对了相同输入、公开语句、承诺、PCS 参数，以及同协议在不同模式、线程和实验批次中的证明字节一致性。
- 消融的两个六线程批次检测到并发构建，整批保留并排除，第三批通过；规模实验十个配置均首批通过。没有按耗时筛样本。
- 正式实验保存原始 JSONL、执行日志、源码/可执行文件哈希及当时源码压缩包；默认模式改动前的消融版本也已归档。
- 最终核对原快照的 308 个复制文件和 2 个生成文件，310 个 SHA-256 均保持不变。
