# GF(256) 系数建表方案与现有 Mikros Hadamard

已实现并在服务器完成比较。直接系数方案使用 GFNI/AVX-512 后，在本次 N=2^14、2^16 测试中更快；在 N=2^30 时比现有 PairAggregate 慢 53%。纯乘法查表版本在全部已测规模都更慢。这是当前实现的实验结果，不能推断所有系数域算法或一个精确的切换阈值。

N30 的 GFNI 系数法用时为现有 Mikros 的 1.530 倍，纯查表为 22.563 倍。N20 的两条 native 路径接近，样本不足以判断细小差异的显著性。小规模结果并不单调：系数路径使用 512 行外层任务，Pair 使用 2048 行，线程调度和任务数量也影响结果，不能只按 GF256 乘法次数解释运行时间。

## 乘法次数应如何比较

每行有 κ 个 binary 输入，K=GF(256)。朴素地把 A、B 插值到 κ−1 个补点，有 2κ(κ−1) 个 bit×K 标量因子；把 A、B 转成单项式系数，有 2κ² 个这样的因子。由于输入 bit 只能是 0 或 1，两者都是选择/XOR，并可用输入字节查表加速，不是任意 K×K 乘法。

完成编码后，补点路径只需 κ−1 个有效 K×K 点乘，H 上则直接 bit AND。完整 schoolbook 卷积另外需要 κ² 次 K×K 乘法与 (κ−1)² 次加法；约 2κ² 指乘法和加法合计。实验进一步只计算求商需要的高半部分，把卷积降为 κ(κ−1)/2 次乘法：κ=128 时为 8128 次，相比 127 个有效补点乘积。

因此 127 与 8128 只比较乘积阶段，不包括线性编码，也不是整个首轮或整个 prover 的运算数。两条完整方案都可以写成 O(Nκ)，相同的阶数不意味着实现成本相同。

系数路径已加入 512 KiB 的 byte-XOR 系数表、高半卷积、稀疏单首项除法，并复用 Pair 的 64 行寄存器加权累加器。当前 Pair 的补点热点表为 32 KiB。该实验没有测量硬件缓存计数器，不能把全部差距归因于缓存。

## 大规模差距来自哪里

以下是独立 profile 进程的 4 次中位数，不能与上面的普通计时跨进程相减。Certificate 在每份记录中先计算 aggregate + quotient，再取中位数，不能直接相加两个分项中位数。

| N=2^30，ms | 聚合 | 商恢复 | Certificate |
|---|---:|---:|---:|
| Pair | 17.281578 | 0.430975 | 17.864966 |
| 系数：乘法查表 | 1398.494568 | 0.016840 | 1398.518144 |
| 系数：GFNI/AVX-512 | 47.937376 | 0.026453 | 47.999317 |

系数方案的商恢复确实更便宜，但新增的逐行编码/卷积成本超过了这项固定节省。小输入时固定节省可以占优势；大输入时行数增长使卷积代价占主导。本次结果支持保留其为可选实验路径，不能据此把所有规模的默认实现替换成系数法。

## 计时范围与验证

- 同一可执行文件、同一批 packed binary 输入、κ=128、GF(256) 中间域与 GF(2^128) 扩域。Flock 跳过 7 轮。
- 固定公共表初始化计入每个进程首次证明；稳态结果排除 warmup。输入相关的系数转换、逐行乘积和随机权重计算全部计入 online，没有缓存展开的 witness 产品。
- 所有 Mikros 路径保留完全相同的证明字节、声明和挑战顺序，IP 尾部相同。完整输入声明检查在计时外。
- 这是直接 packed-opening PIOP 比较，不含 PCS，grinding 关闭，不能视为 E2E SNARK 时间或等安全参数比较。
- Xeon Gold 6342；64 个逻辑线程，affinity 为 0-47,48-55,72-79。48 个物理核加 16 个额外 SMT 线程，两 NUMA 节点各 32 线程，Linux 默认 first-touch。服务器非独占。
- nightly-2026-03-21、target-cpu=native；记录核验 GFNI、AVX-512F/BW、VPCLMULQDQ、PCLMULQDQ、SSE4.1。
- 服务器实际通过 97 项测试；本地最终版通过 96 项。驱动 minimum_tests=96 是验收下限。
- 独立复算通过 21 份 benchmark 报告、378 条证明记录（含 warmup）、54 个输入身份、108 个 family 证明身份。输入、证明摘要、验证标志、轮换位置、全部 summary 和源码/构建指纹均一致。
- N20、N24、N30 各系统保留一次独立新进程冷证明/RSS，原始数据在 evidence 中；单次记录不能当稳定冷启动估计。小规模补测未测 RSS。
