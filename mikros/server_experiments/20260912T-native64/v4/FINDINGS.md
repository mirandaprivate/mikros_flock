# 同压缩比后的结论

当前 `κ = 128 = 2^7`，Flock 已新增跳过 7 轮的优化 PIOP 入口。以下只使用 [v4 同压缩比主实验](EQUAL_COMPRESSION_REPORT.md)，不把旧 Flock64 或另一批次的较快样本混入主表。

## 速度上已有超过的样本，还不能称为稳定领先

N=2^30、64 线程、双方 GFNI/AVX-512/VPCLMUL 与容量复用，六次正式样本：

| 系统 | Prover 中位数 | 范围 | Verifier 中位数 |
|---|---:|---:|---:|
| Mikros 普通复用 | 105.268 ms | 93.181–131.203 ms | 0.2784 ms |
| Mikros 分层权重复用 | 89.729 ms | 81.111–110.019 ms | 0.2414 ms |
| Flock128 | 102.138 ms | 87.789–126.713 ms | 0.7257 ms |

分层 Mikros 的中位数比 Flock128 低 **12.15%**；六组同输入配对中有 **4 组更快**，逐组时间比的中位数为 **0.942**。普通 Mikros 的中位数仍高 3.06%。因此，本批结果支持“优化后的 Mikros 在同压缩比下有可能超过 Flock”，但样本范围明显重叠、服务器非独占，不能外推为稳定或普遍领先。

## 内存优势消失，通信仍然更大

双方现在都是两条长 `N/128 = 2^23` 的初始 F128 尾部向量，共 **256 MiB**，并运行 **23 轮**。旧的“尾部向量减半、少一轮”来自不同压缩参数，不能作为 Mikros 的协议优势。

独立冷进程的峰值 RSS：分层 Mikros **915.30 MiB**，Flock128 **791.97 MiB**。Mikros 多 **123.33 MiB（15.57%）**。Mikros 还显式保存长度 `N/128` 的行权重，单这一数组为 128 MiB；Flock 使用分解后的 equality 表。这个结构与内存差距相符，RSS 本身仍包含输入、线程、表和分配器，不能据一个峰值精确拆出所有分项。

N30 的逻辑证明消息为 **35,776 / 4,880 bytes**，Mikros 约为 Flock128 的 **7.33 倍**；实际 bincode 为 **35,800 / 4,912 bytes**。双方尾部消息数相同，主要差距在首轮：Mikros 的 `3^7=2187` 个列/商系数，对应 Flock128 的两组各 128 个求值。该系数数量比不能直接当作耗时比。

## 剩余优势和瓶颈

Mikros 在 packing 时已把行权重乘入 B，后续是无 equality 权重的内积 sumcheck，verifier 每轮不需要求逆。这使尾部结构较简单，但预加权和完整行权重表的时间、内存仍已计入 prover。Flock 也已使用 friendly constants、split-eq 与四路 VPCLMUL，不能把它当作朴素带权实现。

独立三次 profile 均值中，分层 Mikros 的 tensor 聚合仍需 **47.751 ms**，约占该诊断组总时间的 **54.3%**；A/B packing 为 **14.798 ms**，IP 为 **15.151 ms**。Flock128 的首轮为 **59.970 ms**，融合折叠为 **15.587 ms**，后续 tail 为 **15.447 ms**。每个协议内部最大的阶段仍是首轮。阶段边界不同，不能把某一对阶段的差直接称为完整算法收益。

本批 Mikros verifier 较快，但这是当前实现的结果：Flock128 的两次插值各进行 128 次逐项求逆，tail 还包含逐轮求逆；这些实现成本可以继续优化。不能把实测 verifier 差距当成协议下界。Mikros 自身也要读取和计算 2187 项证书，消息更多并不会免费消失。

Mikros 的 mixed tensor 在二进制输入上便于 XOR/AND、bit slicing 和任意行权重聚合，终端查询保持 tensor 结构；这些是实现与组合上的特点，不保证更快或更安全。当前双方都仅测 PIOP，未包含 commitment、packed opening 或完整 PCS。

## Flock 多跳一轮的独立对照

另起进程的 [Flock 参数组](parameter-sweep-REPORT.md) 各四次正式计时：Flock64 **114.516 ms**，Flock128 **116.457 ms**，中位数接近，后者高 1.69%；二者均有 2/4 组配对更快。此组两个 Flock 参数共用生产容量池，不能和主组交叉拼接时间。

增加跳过轮数会缩短后续向量，但也加大首轮 LDE 和消息。相同压缩比是受控比较条件，并不等同于分别选择两种协议各自最快的参数。本次增加压缩没有显示稳定的总时间收益；Flock128 的冷进程内存更低，消息更大。

## 验证和来源

两个服务器实验组共 **104 份证明记录**（包含 smoke、预热、profile 和 RSS），均通过 PIOP verifier、transcript 状态和全部原始输入声明核验。服务器上的 47 项 Mikros 测试、16 项 skip7 测试、37 项 zerocheck 回归测试及 23 项 NTT 测试全部成功；这些测试集合有重叠，不将其相加称为独立测试总数。计时结束后又链接冻结 binary 使用的同一 Flock rlib，运行两项覆盖全部 GF8 节点的插值测试，均成功。

307 个源码文件的冻结包、逐文件摘要和 43 个下载证据文件均已核验；额外插值测试源单独保存摘要。Mikros 和旧 Flock64 在可配对的 v3/v4 输入上保持证明字节一致。所有跟踪的实验进程已退出。

双方使用 BLAKE3、关闭 grinding，不声称相同 128-bit soundness。CPU 为双路 Xeon Gold 6342，48 个物理核加 16 个 SMT sibling，跨 NUMA 默认 first-touch，无独占 CPU 或 NUMA 绑定。
